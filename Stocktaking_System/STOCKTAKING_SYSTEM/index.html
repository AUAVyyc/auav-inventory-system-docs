    Stocktaking System Documentation

    Overview

    The Stocktaking System provides persistent global state management to control inventory operations during stocktaking periods. When stocktaking mode is active, all inventory modifications (inbound/outbound/update operations) are disabled system-wide to ensure data integrity during stock counting.

    Key Features

    🔒 Persistent State Management

    • Configuration stored in database (system_config table)
    • State survives server restarts
    • Atomic configuration updates

    🛡️ System-wide Protection

    • Blocks all inventory log operations during stocktaking
    • Prevents inventory updates during counting
    • API-level enforcement with clear error messages

    👥 Administrative Control

    • Only Admin users can start/end stocktaking
    • Full audit trail with timestamps and user tracking
    • Real-time status monitoring

    Architecture

    Database Schema

    CREATE TABLE "system_config" (
    "config_key" system_config_key PRIMARY KEY,
    "config_value" text NOT NULL,
    "updated_at" timestamp DEFAULT now() NOT NULL,
    "updated_by" integer REFERENCES "user"("id")
);

    Configuration Keys

    • stocktaking_mode: 'true' or 'false'
    • stocktaking_start_time: ISO timestamp
    • stocktaking_started_by: User ID
    • maintenance_mode: Reserved for future use

    API Endpoints

    • GET /api/system/stocktaking/status - Get current status
    • POST /api/system/stocktaking/start - Start stocktaking (Admin only)
    • POST /api/system/stocktaking/end - End stocktaking (Admin only)

    Usage Guide

    For Administrators

    Starting Stocktaking

    1. Navigate to Dashboard → Admin Portal
    2. Find the "Stocktaking Control" panel
    3. Click "Start Stocktaking"
    4. Confirm in the modal dialog

    What happens: - All inventory operations are immediately blocked - Current timestamp and user are recorded - Status becomes ACTIVE with red badge

    Monitoring Status

    The Stocktaking Control panel shows: - Current status (ACTIVE/INACTIVE) - Start time and initiating user - Warning about disabled operations - Real-time status updates

    Ending Stocktaking

    1. Click "End Stocktaking" button
    2. Confirm in the modal dialog

    What happens: - Inventory operations are re-enabled - Configuration is cleared - Status becomes INACTIVE with green badge

    For Staff Users

    During Normal Operations

    • All inventory functions work normally
    • Inbound/outbound logging available
    • Inventory updates permitted

    During Stocktaking

    • Blocked Operations:
    • Inventory log entries (/api/inventory/log/add)
    • Inventory updates (/api/inventory/item) (PATCH)

    • Any other inventory modifications

    • Available Operations:

    • View inventory (read-only)
    • Search items
    • View reports
    • Non-inventory functions

    Error Messages

    When attempting blocked operations:

    "Inventory log operations is not allowed during stocktaking. 
Please complete stocktaking first."

    Technical Implementation

    System Configuration Service

    File: src/lib/server/system-config.ts

    Key functions: - isStocktakingActive() - Check current status - startStocktaking(userId) - Begin stocktaking mode - endStocktaking(userId) - End stocktaking mode - ensureStocktakingNotActive(operation) - Middleware check

    Protected APIs

    APIs with stocktaking protection: - Inventory log operations - Inventory updates - Future: Order processing, stock adjustments

    Protection pattern:

    await ensureStocktakingNotActive('Operation name');

    Frontend Components

    • StocktakingControl.svelte - Admin control panel
    • Real-time status updates
    • Confirmation modals for safety

    Best Practices

    Stocktaking Workflow

    1. Preparation Phase
    2. Notify all staff of upcoming stocktaking
    3. Complete pending inventory transactions

    4. Generate pre-stocktaking reports

    5. Stocktaking Phase

    6. Admin starts stocktaking mode
    7. Physical counting begins
    8. All inventory changes blocked

    9. Count discrepancies recorded separately

    10. Completion Phase

    11. Physical count verified
    12. Adjustments prepared (offline)
    13. Admin ends stocktaking mode
    14. Adjustments applied to system

    Security Considerations

    • Only Admin role can control stocktaking
    • All configuration changes are audited
    • Database-level persistence prevents bypassing
    • Clear error messages prevent confusion

    Error Handling

    • Graceful degradation when database unavailable
    • Clear user feedback for blocked operations
    • Automatic status refresh in admin panel
    • Comprehensive logging for troubleshooting

    Migration Guide

    Database Migration

    Run the migration script:

    # Apply the migration
npm run db:migrate

    Required Files

    • src/lib/shared/system-config.ts - Type definitions
    • src/lib/server/system-config.ts - Core service
    • src/lib/components/dashboard/StocktakingControl.svelte - UI component
    • src/routes/api/system/stocktaking/** - API endpoints
    • drizzle/0003_add_system_config_table.sql - Database schema

    API Integration

    Add to protected endpoints:

    import { ensureStocktakingNotActive } from '$lib/server/system-config';

// In your API handler:
await ensureStocktakingNotActive('Operation description');

    Troubleshooting

    Common Issues

    Q: Stocktaking won't start - Check user has Admin permissions - Verify database connectivity - Check server logs for errors

    Q: Operations still blocked after ending stocktaking - Refresh admin panel status - Check database system_config table - Restart application if needed

    Q: Status not updating in UI - Click "Refresh" button in admin panel - Check browser network requests - Verify API endpoint accessibility

    Database Queries

    Check current configuration:

    SELECT * FROM system_config;

    Manually end stocktaking (emergency):

    UPDATE system_config 
SET config_value = 'false' 
WHERE config_key = 'stocktaking_mode';
